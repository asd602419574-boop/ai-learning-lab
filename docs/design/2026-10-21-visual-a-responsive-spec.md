## 2. 视觉方向

- 大留白、清楚层级、轻边框与轻阴影，减少无意义的多层嵌套容器。
- 首页围绕一个当前任务组织，主要动作明确；产品界面不显示 R01、P1、P3 等内部编号。
- 宽屏首屏采用 7:5 的任务与成长双栏；比例是布局起点，空间不足时改为单栏。
- 路线使用分段标签切换，默认一次突出 3 张课程卡；保留“查看全部”与自由访问，不把课程总数限制为 3。
- 资源架宽屏 4 列，窄屏依次减列；资源数量从实际目录生成，不硬编码原稿中的 12/144/4/32 作为永久值。
- 个人成长来自本机真实记录，不引入活动区、公开排行、社会动态或需要人工发放的奖励。

## 4. 首页和单课的应用方式

### 4.1 首屏任务与成长快照

左侧突出当前学习任务和一个主按钮。未开始学习时先引导“了解课程安排 → 阅读基础资料 → 看懂完整示范 → 进入配套练习”；返回者可继续上次练习。六步节点仅用于练习进程，对应预测、尝试、观察、解释、重试、迁移，未做过的步骤不显示完成；窄空间允许换行或局部滚动，并完整保留文字与键盘访问。

2026-10-22 首次访问修正历史：首轮曾将主入口明确写为“从第1课开始：认识 AI”，右侧解释“四节入门课 → 六章系统基础 → 按需教材与项目”。用户继续反馈后，当前主入口已改为“了解课程安排，开始基础学习”，先到课程说明与完整16天 / 32单元安排；单课默认先读资料，再显式进入练习。新访客不以三个零指标作为首屏引导；开始练习或存在旧学习记录后，保留续学和真实个人记录。此区别通过已有记录判断，不增加首次访问状态键或强制弹窗。

基础学习概览采用同一白底、浅灰与靛蓝体系：首部并列提供“开始基础资料学习”和“先看16天培训大纲”，紧邻说明培训是集中安排参考、部分专题仍为大纲与任务说明且涉及外部工具。下方分层呈现四课、六章和专题教材，16天日程使用可键盘展开的原生详情，保留实际主题与原专题入口。不得把培训大纲展示成所有内容均已完整实现。

四课 `#lesson?id=课程ID` 默认呈现七段完整正文，长文保持独立阅读行宽，不把资料藏在第四个练习节点；`&view=practice` 显式进入六步练习。已有步骤号与存储保持兼容，阅读入口不新增达标状态。当前概览与正文已在1920、2560、3840、1024、390五种宽度检查无整页横向溢出；本次结果不扩展为实际设备或学习效果验证，P4 未启动。

侧栏目录复用现有章节导航的字号、编号块、圆角和行距，按“学习安排 / 入门资料 / 继续深入”分组。课程显示短标题与副标题，普通项用灰色文字，当前项用浅靛蓝底色并标记 `aria-current`；阅读和练习属于同一课程选中项。首页建议顺序采用相同行样式，不重复主导航的“我的成果”，提示使用小号灰字。目录独立滚动，手机点击后关闭抽屉，末项不得被固定页脚遮挡。

右侧只展示实际可计算的个人记录，例如已保存作品数、练习情况、最近提示使用记录和最近成果。没有记录时呈现空状态与行动建议；不把未定义的“提示依赖度”作为精确能力指标，不编造作品 v2 或成长数据。

## 5. 原生多分辨率的定义

本项目按常见桌面档位将用户所说的 1K 定为 **1920×1080**、2K 定为 **2560×1440**、4K 定为 **3840×2160**。这些是本项目约定；1280/1366 宽度和手机仍应正常响应，不把“1K”当浏览器标准术语。

“原生支持”要求在浏览器正常 100% 缩放下，按实际可用 CSS viewport 排版，无需用户手动缩小网页。禁止用 CSS `zoom`、整页 `transform: scale()`、固定 1920px 画布放大缩小或图片化文字来冒充适配。不能禁用用户自行使用的浏览器缩放。

布局依据可用宽度与容器条件决定，不根据显示器物理宽度或 DPR 强行选择列数。物理像素、CSS 像素、Windows 显示缩放和浏览器缩放分别记录；DPR 主要影响清晰度，不能单独证明布局适配。[MDN：devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)

### 5.1 容器与布局

原稿“全站主容器最大 1140px”在此调整：**应用外壳覆盖可用视口，导航/工作区正常流式布局；1140px 仅为局部阅读/导览容器参考，不能锁死整站工作区。**

| 档位基线 | 首页 | 单课与实践 | 必须避免 |
|---|---|---|---|
| 1K：1920×1080 | 足够空间时 7:5，课程 3 卡、资源 4 列 | 双栏对照，目录/提示可收起 | 遮挡、挤压和为了首屏完整而缩小文字 |
| 2K：2560×1440 | 容器与间距随可用宽度扩展，保持主次 | 可并排目录、学习内容、任务/结果 | 整站仍固定 1140px，以及所有文字被横向拉长 |
| 4K：3840×2160 | 保持呼吸感并有效使用宽度，内容分区扩展 | 适合材料/操作/结果并排，辅助区按需出现 | 中央窄条、控件整体倍增、低分辨率图被拉糊 |

长文正文建议约 `720–880px` 为初始阅读行宽，按字体与用户设置实测微调；外层工作区不受该行宽限制。导航和按钮保持稳定、可操作的尺寸，不按屏幕像素数量机械倍增；标题、正文可使用有限流式字号。

实际 CSS viewport 变窄时，7:5 改上下排列、课程卡 3→2→1、资源 4→2→1，目录/提示变为抽屉或展开区。断点按内容最小可用宽度确定，不把每档名称直接映射为固定设备模式。

SVG/文字/图标保持清晰；Canvas 依据 CSS 显示尺寸与 DPR 设置绘图缓冲，图片提供足够分辨率。需要二维布局的表格、代码或实验可以局部滚动，正文和整页不得被迫横向滚动。[W3C：Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 5.2 Windows 缩放与验收矩阵

开发时先以 CSS viewport `1920×1080`、`2560×1440`、`3840×2160`、DPR 1 建立三档受控基线，浏览器缩放 100%。随后增加 Windows 125%/150%/200% 的代表组合，不必穷举全部排列。

例如 4K 在 150% 下可用逻辑尺寸约为 2560×1440、200% 下约为 1920×1080；浏览器工具栏、窗口状态和系统设置还会改变实际视口，必须读实际值而非直接照抄这些估算。仅设置 `deviceScaleFactor` 不会自动改变 CSS viewport，自动化中两者分别配置。

最小验证范围：三档受控基线；1K+125%、2K+150%、4K+150%/200% 的代表逻辑视口与 DPR；390px 手机与 1024px 过渡宽度；代表页面在浏览器 200% 放大后仍能访问内容和核心操作。至少一个实际 Windows 显示缩放组合人工查看，其余可用受控浏览器环境验证，并如实标注。

覆盖首页、路线标签、教材长文、单课作答、项目/实验、个人成果页。检查布局使用宽度、文字行宽、导航、六步节点、长标题、反馈和主按钮，不只看截图像素或页面是否有横向溢出。

每份证据记录实际 `innerWidth/innerHeight`、DPR、浏览器缩放、系统缩放（能实际确认时）、关键区域尺寸与截图；无法观察的物理显示器参数保持未知。记录中包含界面内容和操作结果，不把模拟截图称作实际 4K 设备验证。

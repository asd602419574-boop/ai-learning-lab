# 当前版本部署说明

适用于当前多静态资源学习站。这里只描述手动发布方法，不表示已部署，也不授权操作生产环境。发布前检查实际分支、Git SHA 和工作区；默认 `main`、开发分支与生产版本可能不同，不能仅凭分支名判断一致。

## 运行与构建

在仓库根目录通过 HTTP 运行，避免 `file://` 下的教材请求与存储差异：

```powershell
python -m http.server 8876 --bind 127.0.0.1
```

访问 <http://127.0.0.1:8876/#home>。修改基础数据或入口模板后运行 `node scripts/build_ui.js`；修改教材后运行 `python scripts/build_textbook.py`。构建需要 Node.js 与 Python，Python 构建依赖及一致性检查命令如下：

```powershell
python -m pip install -r scripts/requirements-build.txt
python scripts/check_generated.py
```

检查器在临时目录重建，比较入口、教材清单及渲染 HTML，不修改工作区；漂移退出 1，依赖或构建失败退出 2。应提交源文件和对应生成产物，不要在服务器上临时修改 HTML 后当作源码版本。仓库 CI 仅验证，不自动发布生产。

## 静态资源与反馈服务边界

从已确认的同一个 Git 提交准备发布目录，保持相对路径。当前静态发布清单为：

| 路径 | 用途 |
|---|---|
| `index.html`、`desktop.css` | 页面入口与公共布局 |
| `learning/` | 首页、课程内容、阅读/练习、备份与成果界面 |
| `content/reader.js`、`content/reader.css`、`content/home.js`、`content/home.css`、`content/manifest.json`、`content/rendered/` | 教材读取与展示；清单引用的 HTML 需全部存在 |
| `projects/` | 四个项目的界面、指南与计算逻辑 |
| `training/` | 培训安排、题目与界面 |
| `feedback/` | 意见反馈前端；提交请求使用同源 `/api/feedback` |

为减少漏文件风险，可以整体复制上述六个资源目录；`content/lessons/`、`content/foundations.js` 等源文件虽不属于阅读器运行必需文件，随同静态资源保留也不替代构建检查。发布清单应随真实依赖变化更新，不以本表长期冻结实现。

**不要将整个仓库作为公网静态根目录。** `.git/`、`.venv/`、`server/`、测试、截图、数据库、备份、环境配置与凭据都不在静态发布清单内。

`server/app.py` 是独立 Flask/SQLite 反馈服务，不负责学习记录同步。只有另外配置该服务及同源代理后，反馈提交与管理才可用；纯静态站仍可学习，但不能据此宣称反馈后端正常。服务定义、代理片段和依赖在 `server/`，仅是部署参考，不能直接覆盖现有配置。密码哈希、数据库位置、允许来源等配置留在服务器本地；数据库及用户反馈不得进入发布目录或仓库。变更后端需单独验证并备份，静态更新不应隐式重启或迁移服务。

## 已授权发布时的最小步骤

1. 确认本次发布授权、目标站点及实际静态根目录，记录 `git rev-parse HEAD` 和 `git status --short`。使用明确的完整提交 SHA 准备干净候选目录，不自动合并开发分支或追随最新 `main`。
2. 运行生成产物一致性检查和本次改动相关测试。用临时 HTTP 服务检查候选目录，确认教材清单、CSS 和 JS 返回正常，首页到课程资料、练习、成果与备份流程可用。
3. 备份现站完整静态发布目录及现有版本记录，保留原路径/切换方式。若后端不变，不将反馈数据库混入静态备份；后端变更时另做一致性备份。
4. 为候选静态文件生成 SHA256 清单，在发布目录外记录完整 Git SHA、构建命令、文件清单和时间。Git SHA 说明来源，逐文件哈希说明实际部署内容，两者一起留存。
5. 按现站已确认的方式整体切换静态资源，避免新 HTML 混用旧 JS/CSS。保留原域名、HTTPS、代理与其他服务；不自动修改 DNS、证书或安全组。
6. 在实际域名核对发布记录中的 SHA、远端文件哈希及资源响应，再验证资料阅读、目录跳转、练习保存与刷新、成果导出/备份。HTTP 200 或提交号本身不等于业务验证；用户旧记录需在原浏览器/域名确认。只有本次包含反馈服务时才验证反馈链路，并明确前后端各自版本。

## 回滚与记录边界

若出现页面或资源加载失败、资料/题目缺失、关键学习流程或旧记录兼容异常，恢复上一份完整静态目录及其版本记录，避免只回退 `index.html`。不清除浏览器 localStorage，不改域名来掩盖兼容问题；学习者可以先在个人成果页导出全站备份（含新增贯穿项目记录）。本地备份不提供云同步，清理存储或更换设备仍可能丢失记录。

当前多标签页写入保护要求支持 Web Locks 的浏览器及 HTTPS 或 localhost；不支持时页面明确只读，不能把普通非 localhost HTTP 访问当作保存兼容性证明。同源、同版本页面只允许一页作答保存，其余可阅读并提示其他页的记录更新；“在此页继续学习”会停止旧页写入，重载此页最新记录后接续作答，并非自动刷新全部页面显示。发布后提醒用户重新加载旧标签页以使用新保护；原有学习存储键与备份格式沿用，不新增账号或云同步。

结束时报告实际发布 SHA、文件核对结果、验证场景、是否回滚及未验证项。没有连接生产和验证实际文件时，只报告候选产物/本地结果，不能写“线上已对齐”。自动生产部署、`main` 合并和服务器配置变更均需另行授权。

# 08｜数据工程、标注质量与交付：把 AI 项目真正做成

> 学习目标：理解数据清洗、标注规范、一致性、版本、误差分析与最小部署闭环；能制定标注作业并计算一致性指标；知道何时需要回滚。

## 数据质量比“把模型调大”更早发生

设想要训练一个区分“活动通知 / 商品广告 / 其他”的文本分类器。你收集的 500 条文本中，可能有重复转发、空白内容、不同语言、日期格式混乱，以及相同内容在不同标注人员手中得到不同标签的问题。如果直接输入模型，训练可能很快，却很难知道高分到底来自学习到有效规律，还是记住了大量重复句子。

数据工程应先处理**来源合法性、格式有效性、数据完整性、重复与异常、隐私风险和标签一致性**。不是所有异常都应无条件删除：罕见但真实的样本可能恰恰是模型上线后的关键困难场景。清洗策略需要写成规则并保存前后样本数量。

## 标注指南是什么？

标注不仅是点选类别，更是对概念边界的定义。例如“本周六图书分享会开始报名”应标为“活动通知”；“低价图书限时购买”是“商品广告”；“图书馆今天停电暂停借阅”到底是活动通知还是其他？如果指南没有定义，两个标注员可能各自合理地做出不同决定。

一份可操作的标注指南应该包括：分类目标、类别定义、正例、反例、边界案例、无法判断时的处理方式、版本号和冲突裁决人。对个人信息应按授权与最小必要原则处理，并避免为了训练收集不必要的字段。

## 一致性为什么比“大家都打过标签”重要？

假设两位标注员对 100 条文本独立标注成 A/B 两类，70 条一致、30 条不同。简单一致率是 70%，但如果 A 类非常常见，那么“都猜 A”也可能产生很高的一致率。Cohen's Kappa 可校正由双方类别分布推算的机会一致率：

`κ = (Pₒ - Pₑ) / (1 - Pₑ)`

其中 `Pₒ` 为观察到的一致比例，`Pₑ` 是根据两位标注员的各类别比例计算出的预期一致比例。比如两人给 A/B 的比例都为 50%/50%，则 `Pₑ=0.5`，若 `Pₒ=0.7`，Kappa 为 `0.4`。这个指标有助于描述一致程度，却不能证明标签本身正确；两个人完全一致地标错也可能有高 Kappa。多标注员、多标签或极度不平衡的情况需要更合适的分析。

## 数据集应当可追溯

```text
来源与许可 → 清洗规则 → 去重/切分 → 标注指南 v1
                                     ↓
            测试集冻结 ← 冲突复核 ← 双人独立标注
                   ↓
        训练与评估 → 错误分析 → 指南 v2 / 新样本
```

每次变更都需要知道：哪些样本增加或移除、标签是否重新裁决、测试集有没有变化、模型权重和预处理器对应哪个版本。至少为数据集保留文件 SHA256、样本数量、标签分布、创建日期、来源许可和清洗脚本版本。避免将个人数据或未经许可的图片误加入公开仓库。

## 从 Notebook 到可交付应用

一份 Jupyter Notebook 能跑通，不代表真实用户能使用。最小的应用闭环通常包括：

1. **入口**：用户能提交样本或上传合法格式的数据；输入错误时有明确提示。
2. **处理**：模型、规则或检索组件能稳定执行，关键步骤可以记录。
3. **输出**：包含结果、必要证据、失败说明与用户可理解的下一步。
4. **测试**：除了正常输入，还覆盖空值、重复、格式问题和故意对抗样本。
5. **部署**：版本可追溯、权限最小化、关键数据有备份且可以回滚。

对于面向公众的学习网站，浏览器本地存储记录进度很方便，但用户换浏览器后可能看不到记录。后续若引入账号同步，就必须同时考虑用户身份、隐私告知、数据迁移、备份和删除机制。在没有需求前，不必为了技术完整性仓促接入数据库。

## 课程综合项目：开放资料分类器

以 50 条自行编写或许可明确的短通知为样本，定义三种标签，并编写不少于 8 条的标注指南。邀请另一名学习者独立标注其中 20 条，在不讨论的情况下先计算一致率，再分析分歧案例并修改指南。用最简单的关键词分类器作为第一版基线，在保留的测试集上输出混淆矩阵。最后制作一个 HTML 页面：可以输入一条通知、获得分类结果并查看规则来源，输入空白、乱码、边界案例时有合理响应。

**最终验收**：README 写明如何运行，数据与标注版本可以检查；提供至少三种边界案例的测试结果；展示一次错误分析和改进，不要只给一个准确率数字；需要手动确认的动作明确提示，不伪称自动执行。

## 两类典型交付错误

**“只展示最佳截图”**：看不到失败样本，也无法判断可重复性。应提供测试样本、代码、版本和输出。**“部署就是复制代码”**：如果依赖包、环境变量、数据路径和权限没管理好，代码在另一台机器可能无法运行。部署前要确认不可泄露密钥、能备份关键数据、能够小范围回滚。

## 检查自己真正掌握了什么

1. 如果标注一致率高而模型仍然经常出错，可能有哪些原因？
2. 什么情形下去重会造成错误删除？
3. 为什么离线测试通过之后，上线仍需要监测输入数据变化？
4. 为什么“系统返回成功文本”不足以证明操作已经持久化？

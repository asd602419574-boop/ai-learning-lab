04｜Transformer 与大语言模型：Token 如何变成回答？

学习目标：理解分词、嵌入、注意力、位置、上下文窗口和自回归生成；避免把模型生成过程误认为数据库查找；识别语言模型常见局限。

从一个问题开始：语言模型到底在做什么？

当你输入“今天适合骑车吗？”时，系统首先把文字转化为模型能处理的 Token 序列。Token 可以对应字、词的一部分、标点或特殊符号，不总是一个汉字对应一个 Token。随后各 Token 映射为向量表示。模型在多层计算中结合上下文信息，给下一个输出 Token 分配概率，再按解码策略选出一个 Token，并重复这一过程。

简化流程可以表示为：

用户文字 → Token 序列 → 向量与位置信息
                         ↓
                Transformer 多层计算
                         ↓
               下一个 Token 概率分布
                         ↓
               采样/选择 → 继续生成

这个过程解释了为什么模型可以写出结构良好的句子，却仍可能对真实天气判断失误：模型本身未必接入实时天气来源。“文字像真的”并不是“事实已经核对”。

注意力解决什么问题？

阅读“河岸旁的树叶落到了水面，它缓缓漂远了”时，我们会根据上下文判断“它”指什么。模型也需要建立跨位置的信息关联。自注意力用查询 Q、键 K、值 V 的计算，让一个位置根据与其他位置的相关性聚合信息。常见形式为 Attention(Q,K,V)=softmax(QKᵀ/√dₖ)V。

不要死背符号，可以按机制理解：Query 表示当前想找什么关系，Key 提供可比较的线索，Value 是被汇总的信息。点积与缩放决定注意力权重，softmax 让权重变成一组总和为 1 的相对值。注意力不是自然语言意义上的“注意力集中”，也不自动等于因果解释。

一个微型计算

假设某 Token 对三个位置的原始得分为 [2,1,0]。softmax 后相对权重大约是 [0.665, 0.245, 0.090]。若三个位置提供的数值为 [10,0,-10]，加权汇总约为 6.65-0.90=5.75。真实 Transformer 的向量维度更高，还会引入多头注意力、前馈网络、归一化和残差连接；微型例子只展示“如何按相关性加权取信息”。

位置为什么重要？

“猫追狗”和“狗追猫”的词集合相同，但事件参与者不同。纯粹的词袋模型难以表达序列顺序。Transformer 需要额外的位置表示或与位置相关的注意力机制，才能区分不同顺序与相对距离。不同模型可能采用绝对位置编码、相对位置偏置、旋转位置编码等不同实现。

上下文窗口限制的是模型在一次请求中可直接处理的 Token 数量；长窗口也不保证模型能同等可靠地使用每个位置的信息。对长资料，通常还需要检索、拆分、摘要与证据检查。

预训练、微调与推理不要混淆

阶段 在做什么 通常是否改变模型参数
预训练 从大量数据中学习语言和知识模式 是
指令微调/偏好优化 调整回答方式与任务能力 通常是
普通推理 用既有模型对当前输入产生输出 否
RAG 检索增强 将外部检索结果放入输入上下文 通常不改变基础模型参数

使用外部文档并不自动更新模型的永久知识。上下文中放入资料，也不保证它会被正确引用。只有在检索、引用和评价链路可见时，才更容易判断结果是否可靠。

解码参数为何影响回答？

温度（temperature）会改变下一个 Token 概率分布的尖锐程度。较低温度倾向于选择高概率候选，较高温度增加多样性，但不必然提高正确性。Top-p 等截断采样策略控制候选范围。对于需要可复现的表格抽取，通常偏向稳定设置；对于创意构思，可以允许更高多样性。不同 API 的参数含义和支持范围可能不同，应以具体模型文档为准。

动手：观察“流畅但错误”的失败

选择三段你可以核对出处的公开材料：一段短百科说明、一段日期公告和一段包含否定条件的规则。给模型相同的问题，分别在“不给材料”和“给材料但要求引用”的条件下生成答案。记录事实错误、漏掉条件、错误引用和拒答情况。不要只按文风打分。

再选择一个存在歧义的句子，例如“老师告诉学生他明天出发”，尝试添加上下文；记录改变哪个细节后模型才正确理解指代。这将帮助你观察上下文条件如何影响概率生成。

核心误区

  • 注意力权重高就说明找到因果原因：不成立。权重是一种模型内部计算，不等同于可信解释。
  • 扩大上下文就消灭幻觉：不成立。长材料也可能发生遗漏、混淆和错误归因。
  • 推理会自动训练出新参数：普通推理不会。
